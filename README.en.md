# UTAU Oto Settings Automation Tool (Autoto)

### &lt;This oto settings estimation software is currently for continuous voicebanks only.&gt;

Autoto automatically estimates UTAU oto settings from WAV files. The estimated results are saved as `oto.ini` in the voicebank folder.

## Credit for generated oto settings

If you publish or distribute an `oto.ini` generated by this software **without changes**, you must credit the software used for estimation as **“Autoto (developed by ふっきんちゃん)”**.
If you edit the generated results and use them as a starting point, credit is optional, but we would appreciate it if you include the same credit.

## Algorithm overview

Autoto estimates oto settings using three methods, based on WAV audio and the kana sequence in file names. It analyzes audio features such as volume, spectrum, periodicity, and fundamental frequency, then looks for candidate boundaries along the sequence of sounds.

1. **Spectrum and volume analysis**: Finds the start of a sound and positions where vowels become stable by detecting changes in spectrum and volume.
2. **Spectrogram image recognition**: Uses a CNN to analyze spectrograms and estimate preutterance positions from learned boundary patterns.
3. **Phoneme position analysis**: Matches audio features against the phoneme sequence, estimates each phoneme's position, and determines oto setting boundaries.

You can select which methods to use. Even when multiple methods are selected, only the estimated preutterance values are combined using the median. Other `oto.ini` values, such as offset, overlap, consonant, and right blank, are based on the spectrum and volume analysis method. Confidence may decrease when a label cannot be interpreted from the voicebank's file names or when repeated vowels make boundaries difficult to identify. Confidence is not a probability of correctness. Check the results in an oto settings editor and adjust them manually as needed.

## Download

Get the distribution files from [GitHub Releases](https://github.com/abschan-dayo/UTAU-Oto-Automation/releases).

- **Windows CPU**: `Autoto-CPU.exe`. Runs on the CPU.
- **Windows CUDA**: `Autoto-CUDA.exe`. Uses a supported NVIDIA GPU and driver when available. If CUDA cannot be used, the app displays a notification and switches to CPU processing.
- **macOS**: `Autoto.dmg`. For Apple Silicon (arm64) only. Intel Macs are not supported.

### Installing on macOS

1. Open `Autoto.dmg`.
2. Drag the displayed `Autoto.app` to the Applications folder.
3. Launch `Autoto.app` from Applications.

Developer ID signing and Apple notarization have not been performed. macOS may display a security warning.

## How to use

1. Launch the CPU or CUDA executable, or launch `Autoto.app` from Applications.
2. Choose the voicebank folder containing WAV files with **Select Folder**. You can also drag the folder onto the window.
3. Select one or more analysis methods and click **Start Analysis**.
4. When analysis finishes, check `oto.ini` in the voicebank folder using an oto settings editor and manually adjust any areas that need correction.

See [Usage and overwrite behavior](docs/使い方.md) for details about saving.

## Integration with vLabeler and Heartbeat

After analysis, Autoto asks whether you want to continue editing in vLabeler. Choose **Yes** to launch vLabeler and open the generated `oto.ini`. The first time, or if vLabeler cannot be found at its saved location, select `vLabeler.exe` on Windows or `vLabeler.app` on macOS. The selected location is saved for next time.

The local settings file stores only the path to the selected vLabeler executable or app. On Windows it is `%LOCALAPPDATA%\UTAU原音設定自動化ツール\設定.json`; on macOS it is `~/Library/Application Support/UTAU原音設定自動化ツール/設定.json`.

Autoto uses vLabeler's Heartbeat communication to check whether it is running and responding. If vLabeler is not running, Autoto attempts to launch it, then sends a request to open the voicebank folder and generated oto settings after vLabeler responds. Here, Heartbeat is used for app-to-app response checks; it does not make vLabeler follow the playback position. vLabeler itself is not bundled with Autoto.

## Saving and backing up `oto.ini`

- If no `oto.ini` exists, a new one is created.
- If an `oto.ini` already exists, Autoto asks for overwrite confirmation before analysis starts. Choose **Yes** to replace it. Choose **No** to run analysis and save `oto.ini` in a new `生成済み` folder under the voicebank folder's parent directory. Cancel stops the operation before analysis starts.
- When overwriting for the first time, the original `oto.ini` is saved as `oto_backup.ini`. An existing `oto_backup.ini` is preserved.
- If `oto.ini` changes while analysis is running, saving is canceled to avoid overwriting those changes.

Autoto creates `Autoto_クレジットについて.txt` in the output folder to explain the credit requirements for publication and distribution. An existing explanation file with the same name is preserved.

## Progress and logs

WAV loading, feature extraction, and boundary analysis run per WAV and in parallel, so they appear as a single progress item. Completed stages receive a green check mark. After saving, choose **View Results** to see the results.

Operation logs are saved in `キャッシュ/ログ` inside the voicebank folder, with the operation name and timestamp in the file name. Use **Open Log** to view the current log. Logs include the app version and build ID; GPU and execution device and time per analysis method; input formats and conversion counts; success and failure counts; and counts of adopted estimates and fallback values. Clearing the cache preserves logs. Absolute voicebank and output paths, exception messages, and tracebacks are not recorded in logs. Legacy AppData logs are removed only when there are no links or non-log files and deletion is possible with normal permissions.

## Input audio

Before analysis, choose how to handle input WAV files: analyze without standardizing the input, or convert in memory to 44.1 kHz, 16-bit-equivalent, mono audio. Either choice can generate `oto.ini`, and the original WAV files are never modified. When conversion is not selected, model-based methods still resample internally to 44.1 kHz when required by their fixed input format. Stereo audio is downmixed to mono in memory for analysis.

## Verification and notes

- The Windows CUDA version has been verified with Ampere-generation GPUs. Other GPU configurations, including Blackwell-generation GPUs, have not been verified.
- The macOS version is for Apple Silicon. DMG verification, mounting, and analysis processing were checked on macOS 26.6.1. GUI operation has not been verified.
- Confidence is an internal estimation metric. It is not displayed in the app and does not represent accuracy. Always check the generated results.
- This is a beta release. Behavior may vary depending on the operating system, GPU, and driver.

## Data and privacy

Actual voicebank names, personal file paths, original WAV files, existing, estimated, or manually corrected `oto.ini` files, and training data are not included in this repository. Do not include personal information or voicebank information in GitHub Issues or Pull Requests.

In the future, we may invite users to optionally provide `推定後_oto.ini` and `手動修正後_oto.ini` for accuracy improvements and validation. Do not send settings files unless and until we publish a request that specifies how to submit them, their purpose, retention period, and deletion request process. We do not ask users to provide original WAV files.
